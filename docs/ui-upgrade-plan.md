1. 不引入 OpenIM 或其他第三方 IM；不拆分后端微服务、不引入 Docker/Redis/Kafka 等被禁止的基础设施。

5. 保留原协议 `seq`、`clientMsgId`、`message.ack`、`sync.request/response`、已读游标和 WebSocket 重连机制的语义。

7. 原项目采用**单账号单活动连接**，不在本次 UI 改造中实现多设备并行登录。
8. 不删除、不重命名、不得无确认覆盖用户现有文件或目录；改造前先记录现有文件及职责。
9. 默认不运行自动测试、E2E 或压测；遵守 `AGENTS.md` §11。构建检查可以执行；超约 2 分钟/全量/压测/E2E 先申请。

11. 不把参考包（`docs/EiseChat_UI_交互验收包_V1.1/`）的 HTML/CSS/JS、演示数据或演示交互复制进 `apps/web`；实现按 §16 重写。

## 1. 项目目标、范围与成功指标

### 1.1 总目标

在不重写已完成 IM 核心、不修改后端协议的前提下，把现有可用的 Web 前端升级为一套现代、清爽、统一的 EiseChat UI。完成后可以将同一前端业务核心用于 Windows Electron 和 Android Capacitor，并支持长期维护与新增功能。

### 1.2 P0 / P1 / P2 范围

**P0（本轮必须交付）：**

- 设计变量、统一图标与基础组件视觉状态；
- 独立全局左侧导航、二级列表与聊天内容布局；
- 会话列表、聊天头部、文本/系统/图片/文件消息视觉；
- 消息输入框、文件入口、基础 Unicode Emoji 插入；
- 右侧资料 / Emoji 抽屉，默认关闭；
- 登录注册、联系人、群聊、已有的用户/群管理页面统一；
- 断网、重连、发送中、发送失败、空状态、加载状态；
- 已有业务逻辑与接口调用保持一致；
- Web 常见屏幕宽度响应式，以及 Android 布局设计基础。

**P1（P0 后按实际情况补完）：**

- 主题变量预留与偏好存储（优先只启用浅色）；
- 聊天列表的舒适/紧凑密度选择；
- 页面与面板过渡动效、长文本和极端窗口尺寸优化；
- Android 真机触控、软键盘、安全区体验调整（结合原 M5）；
- Electron 窗口缩放、系统字体、边界与通知体验（结合原 M4）。

**P2 / 非本轮：**

- 真正的好友申请/好友关系/好友分组（当前“联系人”不等于好友系统）；
- 消息正文全文检索、收藏/撤回、群已读详情、跨设备草稿云同步；
- GIF/贴纸商店、语音消息、音视频通话、频道/机器人；
- 端到端加密、iOS 原生客户端、公开运营功能；
- 自动更新、多设备登录、Android 系统级离线推送。

### 1.3 成功标准（建议验收阈值）

| 维度 | 合格标准 | 证据方式 |
|---|---|---|
| 品牌一致性 | 核心页面使用同一设计变量和图标体系 | 样式审查、页面截图 |
| 布局 | 正常宽度下左导航 + 列表 + 主区稳定，右栏初始隐藏 | 不同窗口宽度人工检查 |
| 视觉可读性 | 普通文字对比度目标 ≥4.5:1；交互控件可见焦点 | 对比度检查与键盘走查 |
| 消息功能 | 消息、图片、文件、单聊/群聊状态保持原有语义 | 后续获批功能回归 |
| 稳定性 | 页面切换、抽屉开合、滚动不触发错误的发送/重连逻辑 | 逻辑审查与手动验证 |
| 适配 | 窄窗口无横向遮挡主要操作；Android 可安全输入消息 | 响应式检查与原 M5 真机验收 |
| 构建 | `npm run build` 通过；若确有后端影响再验证后端构建 | 实际执行日志 |
| 交付 | 修改文件、原因、验证、实际测试结果、剩余风险齐全 | 每阶段交付记录 |

阈值属于**本计划建议的验收口径**，不是当前代码已经通过的测试结果。

### 1.4 占位功能策略（V1.1 新增）

允许为**已确认要做、但服务端暂时没有接口**的功能先做前端占位，但不得做成误导性的“假功能”：

- 占位入口必须可见但明确标识不可用（灰显/禁用态 + 点击提示“即将上线”）：不提交假请求、不返回假数据、不静默无响应；
- 占位不得阻塞主流程（登录、会话/成员管理、聊天、收发消息、图片/文件、断线重连）；
- 所有占位必须在 **附录 A** 逐条登记（功能、入口、期望接口、计划阶段）；新增占位与更新登记表必须同一提交；
- 后端接口到位后按既有协议/契约接入并移除占位，同时更新登记表与验收用例；
- 统一使用 §3.3 的 `ComingSoonHint` 提示样式，禁止各页面自造假数据页；
- 范围禁止的功能（好友系统、群已读详情、语音/机器人等，见 §1.2 P2）不做占位。

## 2. 目标信息架构（IA）与路由策略

### 2.1 页面结构

```text
EiseChat
├── 未登录
│   ├── 邮箱验证码登录
│   ├── 密码登录（可选）
│   └── 邮箱验证码注册
└── 已登录
    ├── [一级导航] 消息
    │   ├── [二级列表] 全部 / 未读 / 群聊筛选
    │   ├── 具体单聊 / 群聊
    │   └── [右侧按需抽屉] Emoji / 用户资料 / 群资料
    ├── [一级导航] 联系人
    │   ├── 现有用户搜索 / 联系用户
    │   └── 用户资料 / 发起单聊
    ├── [一级导航] 群聊
    │   ├── 已加入群聊
    │   ├── 创建群聊
    │   └── 成员邀请 / 退出 / 移除
    ├── [一级导航] 设置
    │   ├── 外观与主题（仅支持实际落地项）
    │   ├── 通知（仅支持实际落地项）
    │   ├── 账号与安全
    │   └── 连接与关于
    └── [底部] 我的账号 / 退出登录
```

> **现有页面保留（V1.1）：** `/download`（下载页，分发入口）与 `/admin`（管理占位页）不在视觉重构主线，但必须保持可用：UI-03 仅做样式跟随，不改行为、链接与权限（UI-03-08）。

**导航原则：** 一级导航在桌面始终保留当前位置高亮；切换一级导航时，第二栏改变内容，主区域与对应视图协同改变。聊天会话的滚动位置与未发送草稿不应在普通路由切换后丢失（若当前 Store 无草稿功能，则先确保切换不破坏已有输入行为，再决定是否加本地 UI 草稿存储）。

### 2.2 路由落地边界

- UI-00 核查现有路由/页面，优先沿用路由定义；不得为整齐而批量重命名页面或 URL。
- 统一将“当前一级导航”“当前选中会话”“右侧打开面板”作为清晰的**展示状态**，与消息事实数据分离。
- 保持刷新后从 IndexedDB 展示已有本地缓存并后台补拉的体验。
- “消息搜索”可先放灰显占位入口（点击提示“即将上线”），但**不得返回假结果**；已有用户搜索与会话筛选必须清楚区分。
- **运行态路由约束（V1.1 新增）：** 不得改路由模式——Web 部署用 `createWebHistory`、Electron `file://` 打包态用 `createWebHashHistory`（`apps/web/src/router/index.ts` 已按协议切换）；新增页面沿用该机制；`vite.config.ts` 的 `base: './'` 不得改成绝对路径，否则 Electron 打包态白屏（M4-07 已踩过）。
- **服务器地址约束（V1.1 新增）：** 登录页与设置页必须保留服务器地址配置入口（首次启动必填），存储键 `eisechat.serverUrl` 与设备标识键不变；桌面壳 preload 注入的地址只读，不得被表单覆盖。

## 3. 设计系统规范（Design System）

### 3.1 颜色变量

| Token（建议名称） | 色值 | 使用场景 |
|---|---|---|
| `--ec-brand-500` | `#3D82F6` | 品牌主色、图标、悬停/强调；**不承载白字正文**（白字约 3.7:1） |
| `--ec-brand-600` | `#1769D2` | 主按钮底色、发送气泡、选中文字（白字约 5.3:1，达标） |
| `--ec-brand-050` | `#E8F2FF` | 选中会话、菜单项背景 |
| `--ec-nav-bg` | `#F2F6FC` | 全局导航底色 |
| `--ec-list-bg` | `#FFFFFF` | 会话列表底色 |
| `--ec-chat-bg-a` | `#FCFEFF` | 聊天渐变起点 |
| `--ec-chat-bg-b` | `#EDF5FF` | 聊天渐变中间色 |
| `--ec-chat-bg-c` | `#F5F9FF` | 聊天渐变过渡色 |
| `--ec-chat-bg-d` | `#EAF3FF` | 聊天渐变终点 |
| `--ec-text-primary` | `#26364A` | 主要文字 |
| `--ec-text-secondary` | `#5F6E80` | 时间、预览摘要等次要正文（白底约 4.9:1） |
| `--ec-text-tertiary` | `#8290A3` | 仅装饰性标签/禁用文本（白底约 3.3:1，不承载正文） |
| `--ec-border` | `#E7EDF5` | 分割线与边框 |
| `--ec-success` | `#34B985` | 在线、成功状态 |
| `--ec-danger` | `#C44747` | 发送失败与危险操作 |
| `--ec-focus-ring` | `#1769D2` | 键盘焦点环（2px，偏移 2px） |
| `--ec-disabled` | `#A8B2BF` | 禁用文本/图标 |
| `--ec-scrim` | `rgba(20, 30, 45, 0.42)` | 抽屉/弹窗遮罩 |

建议聊天背景（由 CSS 变量构成，不对页面重复写死色值）：

```css
background: linear-gradient(
  140deg,
  var(--ec-chat-bg-a) 0%,
  var(--ec-chat-bg-b) 47%,
  var(--ec-chat-bg-c) 78%,
  var(--ec-chat-bg-d) 100%
);
```

**对比度规则（V1.1 补算）：** 正文/按钮文字必须 ≥4.5:1。`#3D82F6` 配白字约 3.7:1、`#8290A3` 配白底约 3.3:1，均不达标——品牌蓝只用于图标/强调，主按钮用 `--ec-brand-600`（白字约 5.3:1）；次要正文用 `#5F6E80`（约 4.9:1）；选中项“品牌蓝文字 + `--ec-brand-050` 底”也需用 brand-600（约 4.7:1）。淡蓝只用于选中背景或轻提示，不承载正文。用户上传的视觉参考是灵感来源，不以像素级复制为目标。

### 3.2 字体、字号、间距、圆角

| 分类 | 规范 |
|---|---|
| 中英文字体 | 系统优先：`Inter`（存在时）、`Segoe UI`、`Microsoft YaHei`、`PingFang SC`、系统 sans-serif；不捆绑字体文件 |
| 图标 | **内联 SVG**（组件内或 `assets/icons`），不新增图标库依赖、不使用第三方品牌图标；统一 18px/1.8 描边 |
| 页面标题 | 18–22px，600–700 字重 |
| 一级/二级导航 | 13–14px，选中 600 字重 |
| 聊天正文 | 桌面 14px、建议 1.5 行高；Android 14–16sp 视适配结果 |
| 次要信息 | 11–12px，避免极小字号承载重要文本 |
| 基础间距 | 4px 基数；常用 8/12/16/20/24px |
| 按钮最小热区 | 桌面推荐 ≥36×36px；触摸控件目标优先 ≥44×44 CSS px/dp 等效 |
| 输入框圆角 | 12px |
| 消息气泡 | 14px，收尾角约 4–6px；兼顾群聊头像 |
| 面板/弹窗 | 12–16px |
| 动画 | 120–200ms；尊重 `prefers-reduced-motion` |

> 字体/Emoji 决策（V1.1）：不捆绑字体文件；Emoji 使用 Unicode 字符插入，不引入表情 SDK/字体包。

### 3.3 基础组件清单

| 组件 | 必须支持的状态 | 用途 |
|---|---|---|
| `AppButton`（或复用现有） | 默认、悬停、按下、禁用、加载、聚焦 | 登录、发送、新建 |
| `AppInput` / `SearchInput` | 默认、聚焦、错误、禁用、清空 | 登录、会话/用户搜索 |
| `Avatar` / `PresenceDot` | 图片/文本占位、在线/离线 | 用户与群 |
| `UnreadBadge` | 0、1～99、99+ | 会话未读 |
| `Tabs` / `NavItem` | 默认、悬停、选中、键盘聚焦 | 筛选与导航 |
| `Dialog` / `Drawer` | 打开、关闭、遮罩、焦点恢复 | 建群、确认、右侧资料 |
| `EmptyState` / `InlineAlert` | 空、错误、离线、重试 | 非正常状态 |
| `ComingSoonHint` | 禁用态入口 + “即将上线”提示（不提交请求） | 占位功能（见 §1.4、附录 A） |
| `FileCard` / `ImagePreview` | 加载、完成、失败、不可访问 | 附件 |
| `MessageBubble` / `MessageStatus` | 自己/他人/系统、发送中/成功/失败 | 聊天核心 |

原则：优先改造**已有组件**，只有重复逻辑明显时才抽取共享层；不要一次性造大型组件库。

可访问性（V1.1）：消息列表容器使用 `role="log"` 与 `aria-live="polite"`；交互控件需可 Tab 到达、有可见焦点；抽屉关闭后焦点返回触发按钮。

## 4. 布局与响应式规则

### 4.1 桌面标准结构

```text
┌──────────────────────┬────────────────────────┬────────────────────────────────┐
│ 全局导航 168px       │ 二级列表 300px         │ 内容工作区（弹性填充）          │
│                      │                        │                                │
│ EiseChat / 账号       │ 搜索 / 筛选 / 列表      │ 顶部会话工具栏                  │
│ 消息                 │                        │                                │
│ 联系人               │                        │ 柔和蓝白渐变消息区              │
│ 群聊                 │                        │                                │
│                      │                        │ 消息输入区                      │
│ 设置 / 退出          │                        │                                │
└──────────────────────┴────────────────────────┴────────────────────────────────┘
                                   右侧资料/Emoji 抽屉：默认隐藏，打开约 288px
```

- 左导航：标准建议宽 `168px`，显示图标与文本。
- 二级列表：标准 `300px`，可按实际代码实现 `280–360px` 调节；如有拖动能力须持久化用户偏好。
- 聊天顶栏：高度约 `64px`；输入区最低约 `72px`，多行最高约 `180px`。
- 聊天气泡：相对消息区最大约 `70%～78%`，同时设置约 `520px` 的文字阅读最大宽度；窄窗优先按可用空间约束。
- 右侧面板：标准 `288px`，**默认 hidden**；只允许一项 `none | emoji | user | group` 激活。

### 4.2 响应式分档（初版建议，UI-00 后可微调）

| 视口/窗口宽度 | 表现 | 右侧面板 |
|---|---|---|
| `≥ 1400px` | 168px 导航 + 300px 列表 + 主区域 | 展开时可采用推挤主区域布局 |
| `1100～1399px` | 常规三段式，聊天宽度优先 | 展开时覆盖聊天区右侧，提供关闭按钮 |
| `801～1099px` | 全局导航可紧凑为图标栏（仍保留入口） | 覆盖式，避免四栏硬挤 |
| `≤ 800px` | 单栏页面切换（列表 ↔ 聊天 ↔ 设置） | 全屏/底部抽屉替代右侧栏 |

说明：Web 窄屏响应不等同于 Android 系统行为；Android 单独处理状态栏、软键盘、返回手势与安全区。

**已知约束（V1.1）：** Electron 最小窗口 `960×640`（`apps/desktop/electron/main.ts`），801～1099 档的紧凑图标栏必须在该窗口下可用；Android `minSdk 26`，老设备 WebView 版本可能较低——避免 `:has()`、`color-mix()`、容器查询等新特性，确需使用时提供降级。支持矩阵：Chrome/Edge 100+、Android System WebView 100+（以目标真机实测为准）、Electron 当前内置 Chromium。

### 4.3 滚动与状态保留

1. 全局导航固定，不跟随会话列表滚动。
2. 会话列表自身滚动，聊天消息区自身滚动；输入框固定在主区域底部。
3. 初次打开会话或用户主动跳到最新消息时，按现有规则上报已读。
4. 查看较早历史消息时，收到新消息**不得强制滚到底**；显示“有新消息”快捷入口，按现有游标/滚动策略决定已读上报。
5. 历史分页加载后维持用户当前阅读位置，不造成明显跳动。
6. 打开 Emoji 面板不丢失输入框草稿和光标位置；切换会话不串草稿。

## 5. 详细页面与组件交互规格

### 5.1 左侧导航栏（NavigationRail）

**结构：** 顶部品牌/用户识别、中段一级功能、底部设置/账号/在线状态。

| 项目 | 规范 |
|---|---|
| 一级入口 | `消息`、`联系人`、`群聊`、`设置` |
| 底部账号 | 个人资料及退出登录操作，不额外占用一个复杂主页 |
| 当前选中 | 浅蓝填充 `#E8F2FF`，图标/文字变品牌蓝，保持统一选中标志 |
| Hover | 浅灰蓝底，150ms 左右过渡 |
| Focus | 显示明显键盘焦点边框；不得依赖仅颜色区分 |
| 图标 | 同一套线性图标，建议 18px 左右 |
| 禁用项 | 不应出现“可点击但无动作”的导航条目 |
| 断线 | 底部状态由绿色在线改成断线/重连说明，不隐藏导航 |

**验收：** 切换 `消息→设置→联系人→消息` 正常，当前高亮正确，会话列表选中关系和消息内容不串页。

### 5.2 会话列表（ConversationList）

- 条目高度建议 68～72px，头像 44px，昵称单行溢出省略，摘要一行省略。
- 展示昵称、最后消息摘要、时间、未读数、发送中/已发送提示（仅数据支持时）。
- 选中会话浅蓝色背景；Hover 只加淡色，不使用过亮蓝色整块背景。
- 顶部搜索必须区分“搜索用户/已有会话”和“消息正文搜索”；消息正文搜索暂无后端接口时可放灰显占位入口（`ComingSoonHint`，点击提示即将上线），**不得返回假结果**。
- 分类筛选 `全部/未读/群聊` 在已有会话数据上实现，不修改 REST API 时先进行本地筛选；未读数仍按真实数据。
- 新建会话按钮提供“发起单聊/创建群聊”，基于当前真实 API。
- 空列表、网络加载、会话失效、被群主移除均有明确状态。
- 不要每次数据推送就重置滚动位置或重新创建整栏 DOM。

**验收：** 时间、摘要、未读数、会话排序与现有数据一致；前后台切换与断线补拉后列表不会重复。

### 5.3 聊天顶栏（ChatHeader）

- 左侧：单聊显示头像/昵称/在线状态；群聊显示群头像/群名/成员数与允许展示的在线统计。
- 右侧：真实可用的更多菜单、资料入口。全局消息搜索未完成时不放可操作的假搜索按钮。
- 点击头像/标题：打开正确类型的 `UserProfileDrawer` 或 `GroupProfileDrawer`。
- 资料面板与 Emoji 面板互斥；同一个按钮再次点击可以收起。
- 页面切换时可关闭面板，但不应影响聊天未发送内容。

### 5.4 消息气泡（MessageBubble）

| 消息/状态 | 样式要求 | 业务约束 |
|---|---|---|
| 他人文本 | 白底、深色字，左对齐，尾角略小 | 按真实 `seq` 排序 |
| 自己文本 | `#1769D2` 蓝底、白字，右对齐 | 不把发送状态硬编码成“已读” |
| 群消息 | 有条件展示发送者昵称/头像，系统消息居中 | 群已读详情本期无实现 |
| 系统消息 | 灰蓝胶囊或中性区块 | 使用服务端真实系统消息内容 |
| 图片消息 | 缩略图、合适比例、点击预览 | 复用鉴权下载，不直连磁盘路径 |
| 文件消息 | 文件类型图标、名称、大小、下载/预览 | 走授权 API，不暴露 storage_path |
| 长文本 | 换行、超长 URL/单词断行、可选择复制 | 不截断服务器真实正文 |
| 发送中 | 时钟/加载态 | 发送队列尚未收到 ACK |
| 已发送 | 单勾或同义文案 | 收到 `message.ack` |
| 已读 | 双勾或“已读” | **仅在单聊且读游标覆盖该消息时展示** |
| 失败 | 红色说明 + 重试按钮 | 现有 2s/5s/10s 重试策略结束后 |

**重要：** 双勾不能简单由消息已经落库推断；群聊目前不显示成员已读详情。消息组件只消费现有 Store 与协议派生出的可信状态。

### 5.5 输入框（MessageComposer）

- 文本输入自动增长至约 180px，超过后内部滚动；保留发送按钮。
- `Enter` 发送、`Shift+Enter` 换行，处理中文输入法 `compositionstart/compositionend`，避免候选词确认时误发。
- 附件入口与图片入口调用已有文件上传/图片压缩逻辑；展示上传中、取消/失败（若当前已有相应能力）。
- 基础 Emoji 采用 Unicode 字符选择并插入当前光标处；**点击表情不立即发消息**，不要求商业表情 SDK。
- 空内容与纯空白不可发送；超过现有文本长度限制应按真实服务端限制提示，不擅自放大限制。
- 发送失败后原消息保留在列表中并可重发，不能丢失 `clientMsgId` 的幂等语义。
- 会话/窗口切换优先保护输入草稿；本地草稿若新实现，明确仅是本机 UI 状态，不是跨设备同步。

### 5.6 右侧抽屉（RightSidePanel）

**产品决策：** 默认 `none`，绝不因进入聊天自动弹出 Emoji 面板。

| 打开类型 | 触发 | 内容 | 关闭方式 |
|---|---|---|---|
| `emoji` | 输入框 Emoji 按钮 | 分类、常用表情、选择插入 | 再点按钮、关闭、Esc |
| `user` | 单聊头像/昵称 | 用户资料、在线状态、可用的联系信息 | 关闭、Esc、切换页面 |
| `group` | 群聊头像/群名 | 群成员、邀请、退出/移除等已有能力 | 关闭、Esc、切换页面 |

- 任意时刻最多一个抽屉打开；抽屉不应该覆盖发送按钮或使输入框不可用。
- 覆盖式抽屉按 `dialog`/合适的辅助技术语义管理焦点；关闭后焦点返回触发按钮。
- 群成员及其操作只根据当前用户角色/权限展示，不增加不存在的群管理接口。
- “共享文件汇总”若无聚合接口，可放灰显占位入口（提示即将上线）；文件仍从聊天消息中正常打开。

### 5.7 登录、注册与认证相关页面

- 桌面登录采用左侧品牌说明 + 右侧表单的简洁布局；移动端为单栏。
- 现有三模式：邮箱验证码登录、邮箱密码登录、邮箱验证码注册。
- 验证码发送 60s 冷却与服务端限流状态以**真实返回**为准，展示清晰错误提示。
- 登录失败不重置所有输入；密码可显示/隐藏，但不得泄露在日志或 URL。
- 认证过期、被另一设备登录踢下线，展示不同原因；遵循现有 `kicked` 行为。
- 不增加手机号登录入口；忘记密码后端未实现时可放灰显占位提示，不提交假请求。
- **服务器地址（V1.1 必保）：** 保留服务器地址配置（首次启动必填、可修改），存储键 `eisechat.serverUrl` 不变；桌面壳 preload 注入地址时字段只读；不因重排布局隐藏或移除该项。
- 认证过期/被踢的提示沿用现有 `kicked` 行为，不新增假状态。

### 5.8 联系人页与用户资料

- 顶部提供当前实现的昵称/邮箱模糊搜索；搜索无结果、加载失败各有状态。
- 从列表选中后，主区域显示用户昵称、在线状态、邮箱（按服务端实际返回字段）与“发送消息”。
- 不误称“已互加好友”，不显示好友申请状态（现有文档不支持）。
- 首次发起单聊和打开已存在单聊，均调用原会话创建/复用流程。

### 5.9 群聊页和群资料

- 仅展示当前账号已加入的群聊；可用现有接口创建、邀请、退出、移除。
- 按权限控制操作显示：群主与普通成员操作不同；群主不可退出/转让等现行限制照旧。
- 危险操作明确二次确认，但不引入与 API 语义不一致的额外“解散群”入口。
- 群成员头像、昵称、在线状态清晰；成员移除后会话状态按服务端通知更新。

### 5.10 设置中心

**建议分类：**

1. **外观与主题：** 浅色（本轮启用）、深色（设计预留）、消息字号/密度、渐变背景（按已实现偏好能力呈现）。
2. **通知：** 当前浏览器/桌面客户端运行时可实现的消息通知或提示音，平台不支持时说明或隐藏。
3. **账号与安全：** 当前用户资料、已实现的密码更改能力、退出登录等。
4. **连接与关于：** WebSocket 当前状态、版本、必要诊断信息，绝不展示 JWT/验证码/密钥。

**设置持久化策略：** 与服务器无关的纯视觉偏好优先客户端本地存储；涉及账号信息的修改必须调用既有真实接口。对所有尚未实现的设置项，不提供虚假的可操作开关。

- **关于与下载（V1.1 新增）：** 保留“下载客户端”入口（链到现有 `/download`），显示当前版本号；未实现的通知/提示音等设置项允许灰显占位（说明“即将上线”），不得提交假请求。

### 5.11 弹窗、空状态、异常状态清单

| 场景 | 必须设计的反馈 |
|---|---|
| 未选择会话 | 中央提示“选择聊天开始交流”，主区域保持背景层次 |
| 无会话/无联系人 | 空状态插画或图标 + 合理的下一步入口 |
| 无搜索结果 | 明确“未找到匹配结果”，可清空搜索 |
| 网络断开 | 顶部浅色提示横幅，历史仍可阅读，显示重连中/失败 |
| 消息发送失败 | 原消息下方可重试；无需整屏遮罩 |
| 附件下载失败 | 内联错误信息 + 重试或再次下载 |
| 历史加载中/无更多 | 顶部局部加载指示，保持滚动位置 |
| 会话权限变化 | 展示服务器真实错误/成员移除反馈，不显示无权限操作 |
| 登录过期/被踢 | 清楚说明原因并引导重新登录 |
| 建群确认/移除成员 | 明确目标对象与后果，支持取消 |

## 8. 接口与数据契约保护清单

| 契约 | 本次 UI 应遵守的行为 | 风险点 |
|---|---|---|
| `message.send` | 复用发送队列和 `clientMsgId` | 重复点击导致重复消息 |
| `message.ack` | ACK 后显示已发送 | 乐观消息未与 ACK 合并 |
| `message.new` | 按 `messageId` 去重、会话 `seq` 排序 | 列表重复/乱序 |
| `sync.request/response` | 断线/切回前台后按游标补拉 | 误清 `lastSeq` 或跳过分页 |
| `read.update/read.updated` | 单聊显示真实已读；群聊不做已读详情 | 把已送达误当已读 |
| `typing` | 显示真实输入提示并遵守现有限流 | 长期显示“正在输入” |
| `presence` | 显示真实在线状态 | 断线后仍误标在线 |
| `conv.updated` | 正确更新新会话/群成员变化/移出状态 | UI 显示已移除的群 |
| 文件 REST | 上传/下载鉴权，不暴露服务器文件路径 | 直接拼路径泄漏私有附件 |
| `kicked` / 认证过期 | 进入正确登录状态并解释原因 | 误以为网络故障 |
| 服务器地址/设备标识 | 保留 `eisechat.serverUrl`、设备标识与设置入口；桌面注入地址只读 | 覆盖安装后连不上服务器 |
| Electron/Android 运行态 | 保持 hash 路由、`base: './'`；不改 `appId`/`androidScheme`/`webDir` | 打包白屏、Android 混合内容 |
| 本地缓存 | IndexedDB 库表/键名与清理逻辑（`auth.clearSession`）不变 | 升级后历史消息或未读异常 |

**禁止事项：** 不从界面事件推断服务器已经完成的状态；不重写 WS 心跳、指数退避重连、会话内 `seq`；不把数据仅保存在 IndexedDB；**不得用假数据或不可用按钮伪造占位**（占位必须显式标识并登记，见附录 A）。

### 9.2 工程检验的执行顺序

1. **默认只做代码级静态逻辑自检：** 阅读受影响文件、引用定位、TS 类型与 DTO 对照、样式选择器和交互调用链检查。
2. **允许的构建检查：** `cd apps/web && npm run build`；若后端或协议未改动，通常不需重复构建服务端；需要时执行 `dotnet build server/Chat.Server.sln`。
3. **自动化测试默认不运行。** 需要 Vitest / xUnit / E2E 时先提出范围与理由，遵照 `AGENTS.md` §11 分批执行。
4. 预计超过约 2 分钟的测试、全量测试、E2E、压测，须**先取得用户同意**，不能直接启动。
5. 正式单测按原工程既有位置维护；临时验证脚本仅允许放 `docs/test/`，新建其子目录须先申请，且目录不入 Git。
6. **回归口径（V1.1 补充）：** 每批允许运行 `npm run test:unit`（现有 108 个用例，约 1 秒）作为前端回归；e2e 脚本（`docs/test/`，M3 起 77 项检查）在 UI-02 完成与 UI-05 各申请执行一次；人工验收由用户执行，AI 不得代填“通过”。
7. 未实际执行的项目一律记录“未执行”，绝不写成“通过”。

### 9.3 缺陷分级与发布阻断

- **Blocker：** 不能登录、聊天无法发送/接收、权限越界、消息丢失/重复、敏感信息泄露。
- **High：** 未读/已读错误、群权限错乱、主要设备下输入框被遮挡、文件无法下载、覆盖安装丢失登录态/服务器地址、打包产物无法启动。
- **Medium：** 某些分辨率溢出、动效卡顿、交互不一致、文本截断不合理、占位入口伪造数据或点击报错。
- **Low：** 非关键阴影、边距、图标微调。

Blocker/High 未闭环前不视为 UI 里程碑验收完成；其余可明确记录后续修复计划。

## 10. 风险与控制措施

| 风险 | 可能后果 | 预防/处理 |
|---|---|---|
| 未看源码先批量换页面 | 原有功能/接口失效 | UI-00 文件与调用链盘点；分模块替换 |
| 混用多套组件体系 | 风格不一致、构建体积上升 | 复用已有依赖；先定 Token 再加组件 |
| 为“更像 Telegram”增加功能 | 进度膨胀、协议变更 | 已确定范围 P0/P1/P2；无接口不显示可用按钮 |
| 自己的消息蓝色过亮 | 白字对比度不足 | 发送气泡用深蓝；做对比度走查 |
| Emoji 抽屉占满狭窄聊天窗口 | 输入和消息不可操作 | 右侧默认收起，窄窗覆盖且可关闭 |
| 聊天 DOM 重排 | 消息滚动跳动、未读误上报 | 滚动位置恢复与真实已读边界检查 |

1. **读取规范：** `AGENTS.md` → 主计划相关章节 → **本计划 §16 实现规格** → 当前源文件与调用方。
2. **标注任务：** 使用 `UI-xx-yy` 编号，列明需要修改的文件与理由。
3. **保持小步：** 先 CSS/组件 → 页面布局 → 接入现有 Store；如没有业务必要，不动 API/Core。
4. **静态审查：** 逐项对照实际 DTO、事件、类型、路由以及权限约束；检查是否产生多余依赖和死按钮。
5. **构建：** 按实际变更范围进行构建检查，记录命令和结果。
6. **测试规则：** 遵照第 9.2 节，不默认运行测试；需要测试先说明并申请。
7. **文档：** 更新本计划任务状态、受影响的规范文档和变更记录；新增占位入口时同步附录 A。
8. **交付说明：** 提供五要素：修改文件、修改原因、验证方式、实际测试结果、剩余风险。
9. **Git 安全：** 提交前检查 `git status`、差异及密钥；提交信息使用 `类型：[编号]-简述`；不擅自 push/reset/clean。

## 16. 参考资产与实现规格（V1.2 新增）

> 本章回答一个问题：客户提供的「交互验收包」只作参考，具体代码怎么实现？——组件位置、尺寸、界面文案和演示数据都不照搬；组件怎么拆、放在哪、用什么数据、做到什么程度，由本章定义。UI-00 仍须按真实源码核对后微调，但不得改变本章的组件边界与数据来源原则。

### 16.1 参考资产登记与定位

| 资产 | 路径（待 UI-00 归一） | 规模/内容 | 使用方式 |
|---|---|---|---|
| 客户交互验收包 V1.1 | `docs/EiseChat_UI_交互验收包_V1.1/`，归一后 `docs/ui/acceptance-v1.1/` | 34 个文件约 11MB：离线交互工作台 `index.html`、9 张 1440×900/390×844 参考图、`reference-html/` 与 `interactive-pages/` 各 9 页、`UI-验收标准.md` | **只读参考**：视觉方向、交互路径、验收清单来源 |
| 本计划 §3～§5 | 本文件 | 设计系统、版面与页面规格 | 规格来源（与本章冲突时以本章为准） |

关键约定：

1. 参考包中的**组件位置、尺寸、界面内容（文案、会话名、消息、附件、头像、演示验证码）均仅作方向参考**，不直接采用、不要求逐像素对齐。

3. 参考包的演示交互（模拟发送、演示验证码、仅界面演示上传、非范围入口）一律替换为真实实现，或按 §1.4 显式占位并登记附录 A。
4. 参考包自带的 `UI-验收标准.md` 可作为验收清单来源，但数值口径以 §3.1 token 与 §16.5 区间为准；原型的对比度与演示内容不作为通过证据。
5. 参考包需清理：`index.html` 与 `EiseChat_UI_交互验收工作台.html` 内容重复（各约 3.4MB），UI-00 中确认无引用后删除其一；目录归一在 UI-00-09 执行，归一前先确认无文档引用。

### 16.2 参考→实现五条规则

1. **布局意图优先于像素**：栏位、层级、信息密度、主色氛围遵循参考；具体宽高/圆角按 §16.5 区间与真实内容适配，验收不设逐像素一致。
2. **内容必须真实**：参考图中的文案与数据均为演示数据，禁止复制进代码或入库文档；空态、加载、错误、长文本、超长昵称必须由真实数据驱动，或使用仅限 `Development` 的 mock（不得进入生产构建）。
3. **演示交互禁止照搬**：以真实接口与真实 WS 行为为准；后端未就绪的能力按 §1.4 灰显占位并登记附录 A。
4. **禁止复制 DOM/CSS/JS**：不引入参考包的全局类名或样式前缀，避免与现有样式冲突；图标按参考线条风格重绘为内联 SVG（不新增图标库）。
5. **参考图不是测试证据**：验收记录必须区分「参考对照」与「工程实测」，原型截图不得放入验收通过记录。

### 16.4 组件实现约定

- **目录职责**：`pages/` 只做编排（数据加载、路由守卫、布局拼装）；`components/` 放可复用 UI；`core/` 放纯函数与基础设施；`api/` 放请求封装；`stores/` 放状态。新增文件放对应目录，文件名为 PascalCase。
- **数据流**：组件不直接 `new WebSocket`、不直接 `fetch`；由 store/core 提供数据与动作。组件用 props 接收、emits 输出；禁止在组件内写死演示数据。
- **样式**：组件内 `<style scoped>`；仅 `styles/variables.css` 存放 CSS 变量（对应 §3.1 token）、`styles/global.css` 存放重置与少量全局工具类；新类名统一 `ec-` 前缀，避免与旧样式冲突；避免裸标签选择器与 `!important` 滥用；替换旧样式前确认无引用。
- **响应式**：布局切换用 CSS 媒体查询（`@media (max-width: 800px)` 等，沿用 §4.2），不用 JS 监听 `resize` 切换布局；移动端处理 `safe-area-inset-bottom`。
- **可访问性**：抽屉/面板支持 Esc 关闭且焦点返回触发按钮；装饰图标 `aria-hidden`；输入框有 `aria-label`；Tab 顺序可达。
- **依赖**：不引入 UI 组件库、图标库、动画库、表情库；复杂交互用现有能力或少量自写代码实现。

### 16.6 验收口径修订（与参考包验收标准的关系）
